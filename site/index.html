Un lenguaje pequeño y directo

Tipos estáticos, struct, enum, match, closures, módulos e interpolación de texto. Este programa es real: se compila a un ejecutable nativo y escribe lo que se ve a la derecha.

formas.titan
struct Punto {
    x: int,
    y: int,
}

enum Forma {
    Circulo(int),
    Rect(int),
}

fn area(f: Forma) -> int {
    match f {
        Forma::Circulo(r) => 3 * r * r,
        Forma::Rect(l) => l * l,
    }
}

fn main() {
    let p = Punto { x: 3, y: 4 }
    let formas = [Forma::Circulo(2), Forma::Rect(5)]
    for f in formas {
        println("área = {area(f)}")
    }
    let d = p.x * p.x + p.y * p.y
    println("distancia² = {d}")
}

Dos destinos, una sola herramienta

titan compile genera un ejecutable x86-64 con backend propio (sin ensamblador ni enlazador externos) y titan wasm emite WebAssembly con mapas de fuente. Un backend LLVM genera además ARM64.

Herramientas incluidas

new · check · run · test · build · exec · wasm · repl · debug · lsp · dap · add / fetch / pack / publish (paquetes firmados con Ed25519).

Empezar

Titan se construye desde las fuentes con solo bash y gzip. Hoy el compilador es para Linux x86-64.

terminal
$ git clone https://github.com/alexsndersoto04-source/aio.git
$ cd aio
$ bash selfhost/bootstrap.sh
etapa 1: selfhost/titanc0 (compilador nativo semilla) -> titanc1
etapa 2: titanc1 -> titanc2
etapa 3: titanc2 -> titanc3
# ...tres hashes SHA-256 iguales...
PUNTO FIJO: etapa1 == etapa2 == etapa3 (byte a byte)
listo: selfhost/titan

$ selfhost/titan new hola
$ cd hola && ../selfhost/titan run
  1. La semilla. Un compilador que se compila a sí mismo necesita uno que ya exista: un ejecutable de 650 KB que va dentro del repositorio.
  2. El punto fijo. La semilla compila el compilador; ese resultado se compila a sí mismo, y otra vez. Si las tres copias son idénticas, el compilador se explica solo.
  3. La CLI. Con el compilador resultante se construye selfhost/titan. Tarda unos 3 minutos en total.

Biblioteca estándar completa, escrita en Titan

Las 812 funciones std::* del lenguaje tienen su cuerpo en Titan, sin bibliotecas del sistema detrás. Esto incluye piezas grandes que normalmente se piden prestadas a otro lenguaje.

Red y seguridad

TCP, HTTP/HTTPS, WebSocket, servidor y router, DNS, TLS con validación X.509 (cliente 1.2 y 1.3, servidor 1.3), Ed25519, X25519, RSA, JWT, hashes, AES-GCM, ChaCha20-Poly1305, Argon2.

Datos

Un motor SQLite propio (SQL, JSON, funciones de ventana, triggers, transacciones), clientes de PostgreSQL, MySQL y Redis, JSON, YAML, XML, CSV, gzip, zstd, TAR y ZIP.

IA local

Motor ONNX propio (incluye BERT de tamaño pequeño) y tokenizadores de estilo HuggingFace: WordPiece, BPE y Unigram.

Audio e imagen

Decodificadores de WAV, FLAC y Ogg Vorbis, un motor de audio con EQ y remuestreo; lectura y escritura de PNG, JPEG, GIF, WebP y BMP; códigos QR.

Texto

Unicode, motor de expresiones regulares, normalización, zonas horarias, IDNA, URLs y formato de fechas.

Sistema

Archivos, procesos, señales, tareas y canales, observador de archivos, terminal (TUI, teclado, readline), ventanas y Termux:API.

De dónde viene

TITAN nació como un prototipo escrito en Rust. Cuando el lenguaje fue lo bastante capaz, se reescribió pieza por pieza en el propio Titan —analizador, compilador, biblioteca estándar, herramientas— y cada pieza se comprobó contra la versión original antes de reemplazarla. Al final se borró el Rust. Esa primera versión sigue disponible en el historial de git, bajo la etiqueta ultimo-con-rust.

Lo que todavía no hace

Esta página dice lo que está verificado; lo que falta también está aquí. El detalle completo, con cada limitación, vive en selfhost/ESTADO.md.

  • Plataformas: el compilador empaquetado es para Linux x86-64. macOS, Windows y ARM64/Termux aún no tienen paquete (el backend ARM64 existe, falta empaquetarlo).
  • ONNX / BERT: solo modelos pequeños (archivo ≤ 64 MiB); un BERT-base completo no cabe en este motor.
  • SQLite: sin FTS, R-Tree, ATTACH ni EXPLAIN; no es libsqlite3, es un motor propio con diferencias documentadas.
  • Audio: sin MP3, Opus ni AAC; la salida a un dispositivo de sonido real no se ha podido probar.
  • Navegador: std::web y std::wasm existen en el runtime nativo, pero fuera de un host JavaScript dan error de ejecución.
  • Sin sandbox por capacidades en los ejecutables nativos.
