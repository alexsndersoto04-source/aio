Titan — lenguaje de programación

Tipos comprobados antes de ejecutar y ejecutables nativos para Linux (x86-64 y ARM64, incluido Termux), además de módulos WebAssembly. Incluye una biblioteca estándar amplia: texto, red, bases de datos, criptografía, audio, imágenes e inteligencia artificial local.

Características

Lo esencial de Titan

Tipado estático

El comprobador de tipos rechaza variables inexistentes, tipos incompatibles, argumentos de más o de menos y match no exhaustivos antes de generar nada.

Ejecutables nativos

Genera código de máquina: x86-64 con generador propio, o x86-64 y ARM64 mediante LLVM. Sin máquina virtual al ejecutar.

Tareas y canales

spawn, join, canales con capacidad, select y tiempos límite sobre fibras cooperativas, con detección de bloqueo total.

WebAssembly

titan wasm genera módulos con memoria lineal, strings, arrays, mapas y structs, más un host JavaScript para DOM, fetch y Canvas.

Biblioteca estándar

812 funciones escritas en Titan, sin dependencias externas: datos, red, criptografía, bases de datos, multimedia e IA local.

Herramientas integradas

Una sola CLI: proyectos, pruebas, REPL, depurador, servidores LSP y DAP para editores, y paquetes firmados con Ed25519.

El lenguaje

Cuatro programas reales

Sintaxis con llaves y los elementos habituales: struct, enum con datos, impl, trait, closures, match, Option, Result y el operador ?. Cada ejemplo se ejecutó con el compilador y la salida mostrada es la real.

enums, match y manejo de errores
enum Forma {
    Circulo(float),
    Cuadrado(float),
    Vacio,
}

fn area(f: Forma) -> float {
    match f {
        Forma::Circulo(r) => 3.14159 * r * r,
        Forma::Cuadrado(l) => l * l,
        Forma::Vacio => 0.0,
    }
}

fn dividir(a: int, b: int) -> Result {
    if b == 0 {
        return Result::Err("división por cero")
    }
    Result::Ok(a / b)
}

fn main() {
    let formas = [Forma::Circulo(2.0), Forma::Cuadrado(3.0), Forma::Vacio]
    let areas = formas.map(|f| area(f))
    print("áreas: {areas}")
    match dividir(10, 0) {
        Result::Ok(v) => print("resultado {v}"),
        Result::Err(e) => print("error: {e}"),
    }
}
Salida
áreas: [12.56636, 9, 0]
error: división por cero
spawn, canales y join
fn productor(tx: Sender, n: int) -> int {
    let mut i = 1
    while i <= n {
        send(tx, i * i)
        i += 1
    }
    n
}

fn main() {
    let (tx, rx) = channel(2)
    let tarea = spawn || { productor(tx, 5) }
    let mut suma = 0
    let mut k = 0
    while k < 5 {
        suma += recv(rx)
        k += 1
    }
    print("suma de cuadrados = {suma}")
    print("la tarea envió {join(tarea)} valores")
}
Salida
suma de cuadrados = 55
la tarea envió 5 valores

fn main() {
    let servidor = std::server::start("127.0.0.1:8099")
    print("escuchando en {std::server::local_addr(servidor)}")
    let mut atendidas = 0
    while atendidas < 2 {
        let peticion = std::server::accept(servidor, 30000)
        if peticion >= 0 {
            let ruta = std::server::path(peticion)
            std::server::respond(peticion, 200, "hola desde Titan, ruta {ruta}")
            atendidas += 1
        }
    }
    std::server::stop(servidor)
}

Plataformas

Ejecutables nativos para Linux

Los programas son ejecutables estáticos: el runtime llama directamente al núcleo de Linux, sin biblioteca C. El estado de cada plataforma, sin adornos:

Probada

Linux x86-64

Compilador, herramienta titan y programas generados. Punto fijo del compilador verificado.

Probada en servidor ARM64

Linux ARM64 · Termux

La herramienta compila y ejecuta programas; 95 programas dieron salida idéntica a la de x86-64. Requiere clang y lld. No se ha probado en un teléfono Android.

Disponible

WebAssembly

titan wasm genera el módulo; DOM, eventos, fetch, Canvas 2D y WebGL2 funcionan con un host JavaScript.

Previsto

macOS y Windows

Sin ejecutable por ahora: falta portar el runtime, que usa llamadas directas de Linux.

Desde x86-64 se puede compilar para ARM64 con LLVM: titan compile programa.titan --target aarch64.

Instalación

Construir Titan desde las fuentes

Solo hacen falta bash y gzip. Los paquetes ya compilados para Linux x86-64 y ARM64 se publican en Releases a partir de la versión 1.1; las versiones 1.0.x de esa página son del prototipo antiguo en Rust.

1

Construir

Tarda unos 2–3 minutos.

Linux x86-64
git clone https://github.com/alexsndersoto04-source/aio.git
cd aio
bash selfhost/bootstrap.sh
selfhost/titan version
2

Dejarlo en el PATH

El ejecutable busca su runtime en la carpeta native/ que está a su lado.

enlace simbólico
ln -s "$PWD/selfhost/titan" ~/.local/bin/titan
3

Crear un proyecto

Genera Titan.toml y src/main.titan.

terminal
titan new mi_app
cd mi_app
titan run
Cómo se construye. El repositorio incluye una semilla: una copia ya compilada del compilador (7,7 MB, selfhost/semilla/). bootstrap.sh la usa para compilar el compilador escrito en Titan, que luego se compila a sí mismo dos veces; el script comprueba que las tres versiones sean idénticas byte a byte.
Termux (Android, ARM64). El flujo «Linux ARM64 (Termux)» de GitHub Actions fabrica titan-v1.0.0-linux-aarch64.tar.gz. El instalador selfhost/instalar-termux.sh instala clang y deja titan en el PATH. Ver la guía de Termux.

Estado del proyecto

Qué está verificado y qué no

Verificado

  • Punto fijo: el compilador se compila a sí mismo; las etapas 1, 2 y 3 son idénticas byte a byte.
  • Biblioteca estándar: 812 de 812 funciones con cuerpo en Titan.
  • ARM64 real: 95 programas con salida idéntica a x86-64, en un servidor ARM64 de GitHub Actions.
  • Depurador y DAP: 40 y 20 casos de prueba en x86-64.
  • Integración continua: pruebas en GitHub Actions en cada cambio.

Límites conocidos

  • Plataformas: sin ejecutable para macOS ni Windows; ARM64 sin probar en un teléfono.
  • Permisos: los ejecutables nativos no tienen sandbox; un programa puede leer archivos, lanzar procesos y usar la red.
  • Lenguaje: sin genéricos definidos por el usuario, referencias ni break con valor.
  • Tareas: fibras cooperativas, sin paralelismo entre núcleos; no se puede limitar la memoria por tarea.
  • Audio: WAV, FLAC y Ogg Vorbis; sin MP3, Opus ni AAC. La salida a altavoces no se ha probado con hardware real.
  • SQLite: sin FTS, RTREE, ATTACH ni tablas temporales.
  • IA: ONNX y BERT para modelos pequeños (hasta 64 MiB).

El detalle de cada pieza está en el estado verificado.
