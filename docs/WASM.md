# TITAN WebAssembly Backend

`titan wasm <project>` emits a real WebAssembly module with exported `main` and named functions. The backend lowers integer/bool/nil constants, locals, arithmetic, signed division/remainder, logical and bitwise operations, comparisons, direct calls and returns to Wasm instructions.

Titan's bytecode control-flow graph is validated with a work-list stack analysis. Straight-line functions are emitted directly with no program-counter local, dispatch loop, comparisons, or branch table. Canonical `if`/`else` regions are recognized recursively from their forward conditional/join jumps and lowered to nested native Wasm `if`/`else` constructs, with branch values retained in statically assigned locals. Canonical `while` loops are recognized from a forward false-exit and a final backward edge, then lowered to native outer `block` + inner `loop` + `br_if`; nested direct `if` and loops are recursively supported. Reachable jumps to the active loop header/end become depth-correct `br` instructions, so conditional `continue` and `break` inside nested direct `if` regions no longer force dispatch. Unreachable synthetic join jumps are omitted while their absence is reflected in source metadata. Arbitrary cross-region CFGs retain the O(1) `br_table` fallback. This supports `if`/`else`, lazy boolean expressions, `while`, `loop`, `break`, and `continue` without embedding or calling the Titan VM. Invalid branch targets, stack underflow, inconsistent merge heights, bad locals/calls, and declared stack-limit violations produce compilation errors. Generated bytes, including forward branches and backward loops, are validated in tests with `wasmparser`.

UTF-8 string literals are stored in an exported Wasm 32-bit linear memory. A string value uses an `i64` ABI handle: the low 32 bits are the byte pointer and the high 32 bits are the byte length, so JavaScript can decode it without copying through the Titan VM. Four bytes immediately before the payload store the Unicode scalar count; Titan `len(string)` loads that count and therefore preserves Titan/VM Unicode semantics rather than returning UTF-8 bytes. Memory sizing is calculated from the complete string table, overflows are rejected, and invalid string-table references fail compilation.

Modules using single-argument `print`/`println` now import the real host function `titan.print: (i64) -> ()`. Modules without printing remain import-free. Function indexes and exports are relocated automatically when the import is present, including calls between Titan functions. A browser or JavaScript host can interpret the raw `i64` as a number or decode it as the string handle described above. Multi-argument printing is rejected until typed host-value metadata is available.

String `+` is lowered to an internal Wasm concatenation function when bytecode data-flow proves both operands are strings. The helper uses a mutable bump-heap pointer, grows linear memory on demand, checks address overflow and `memory.grow` failure, copies both UTF-8 payloads with `memory.copy`, combines Unicode scalar counts, and returns a new ABI handle. A local type-flow analysis tracks strings through locals, duplication, branches and chained concatenations while leaving numeric `+` as `i64.add`; ambiguous mixed values are rejected rather than guessed. The allocator intentionally does not reclaim individual strings yet.

The browser backend recognizes `std::web::query_exists`, `set_text`, `set_html`, `set_attribute`, `add_class`, `remove_class`, `focus`, and `set_title`. Only imports actually referenced by bytecode are emitted, in deterministic order, and all defined-function indexes are relocated by the exact import count. String arguments use the same checked ABI handles; setters return Titan `nil`, while `query_exists` returns an `i64` boolean. On the native VM these functions fail with a clear browser-host-required error instead of pretending to manipulate a DOM. `set_html` deliberately exposes raw `innerHTML`; applications must not pass untrusted markup.

DOM events use `std::web::listen(selector, event_name, handler_export) -> Int` and `std::web::unlisten(id) -> Bool`. The browser host installs a real `addEventListener`, retains its callback by numeric subscription ID, and invokes the named exported zero-argument Titan function when the event fires. `unlisten` calls `removeEventListener` with the original callback and releases the host record. Handler lookup and execution failures are reported to the browser console without corrupting the Wasm instance.

During a handler, `std::web::event_type`, `event_value`, `event_key`, `event_target_id`, `event_checked`, `event_x`, and `event_y` expose the active DOM event. String values travel host-to-Wasm through the exported `__titan_alloc_string(byte_length, scalar_length)` ABI. The JavaScript adapter UTF-8 encodes the value, invokes the reentrant checked allocator, refreshes its memory view after possible `memory.grow`, writes the payload, and returns the normal Titan string handle. Event context is restored in `finally`, so nested dispatch cannot leak the wrong event. Outside a handler, string accessors return empty strings and numeric/boolean accessors return zero.

Asynchronous GET requests use `std::web::fetch(url, maximum_bytes, timeout_ms, handler_export) -> Int`. Configurable requests use `std::web::request(method, url, headers_json, body, maximum_bytes, timeout_ms, handler_export) -> Int`; header JSON must be an object of string values, CR/LF injection is rejected, methods are token-validated, and GET/HEAD bodies are forbidden. `std::web::fetch_cancel(id) -> Bool` aborts and suppresses its callback. Responses are streamed with a hard byte limit rather than buffered without bounds. The host uses `AbortController` for cancellation/timeouts, retains HTTP status/final URL/body/error/normalized headers in a scoped callback context, and invokes the exported zero-argument Titan handler after completion. That handler reads `fetch_ok`, `fetch_status`, `fetch_body`, `fetch_url`, `fetch_error`, and `fetch_headers` (JSON). HTTP error statuses still expose their status/body; transport errors and timeouts use status zero. Browser CORS and forbidden-header policy remain enforced.

A complete host adapter and page live under `examples/browser/`. Build and serve it with:

```bash
titan wasm examples/browser/main.titan --output examples/browser/program.wasm
cd examples/browser
python3 -m http.server 8080
```

Then open `http://localhost:8080`. Browsers generally forbid loading Wasm from `file://`, so an HTTP server is required.

Browser WebSockets use `std::web::ws_connect(url, protocols_json, maximum_message_bytes, on_open, on_message, on_error, on_close) -> Int`, plus `ws_send(id, text) -> Bool` and `ws_close(id, code, reason) -> Bool`. Separate callbacks avoid comparing erased string handles to determine event type. Within callbacks, `ws_id`, `ws_message`, `ws_protocol`, `ws_close_code`, `ws_close_reason`, `ws_was_clean`, and `ws_error` expose scoped state. The host validates protocol arrays, tracks sockets by ID, limits incoming/outgoing UTF-8 bytes, applies `bufferedAmount` backpressure, handles text and binary frames as UTF-8 strings, reports transport/size/type failures, enforces browser close-code/reason constraints, and releases records on close. The browser controls TLS, origin, proxy and certificate policy.

```titan
fn socket_open() {
    std::web::ws_send(std::web::ws_id(), "hello from TITAN");
    0
}
fn socket_message() { println(std::web::ws_message()); 0 }
fn socket_error() { println(std::web::ws_error()); 0 }
fn socket_close() { println(std::web::ws_close_reason()); 0 }
fn main() {
    std::web::ws_connect("wss://example.com/socket", "[]", 65536,
        "socket_open", "socket_message", "socket_error", "socket_close")
}
```

Canvas 2D drawing uses `std::web::canvas_resize`, `canvas_clear`, `canvas_fill_rect`, `canvas_stroke_rect`, `canvas_line`, and `canvas_text`. Selectors must resolve to `HTMLCanvasElement`; missing 2D contexts trap with explicit host errors. Dimensions, coordinates and line widths are range-checked before conversion from the `i64` ABI. Every draw operation brackets mutable context state with `save`/`restore`, resize is capped at 16384 pixels per axis and 67108864 total pixels, while line width is capped at 10000.

Animation uses `std::web::animation_start(handler_export) -> Int` and `animation_cancel(id) -> Bool`. Each active subscription owns one `requestAnimationFrame` chain, so callbacks cannot accumulate faster than browser frames. Inside the exported zero-argument handler, `frame_id`, `frame_time_ms`, `frame_delta_ms`, and `frame_count` expose scoped integer timing. Cancellation from inside the handler is safe; hidden tabs inherit browser throttling; a trapping handler is logged and automatically removed to prevent an error loop. The browser example animates Canvas using the high-resolution frame timestamp.

Every module embeds a versioned `titan.source_map` custom section and `titan wasm` writes the expanded logical metadata as `<output>.wasm.map.json`. CLI source paths are made project-relative when possible. The backend inserts semantic no-op markers at each reachable Titan instruction, finishes the binary, reparses function bodies with `wasmparser`, and records each marker's absolute Wasm byte offset. The logical map therefore contains import relocation, Titan/Wasm function indexes, operation names, byte spans, lines, columns, and exact generated offsets.

The CLI also emits a standard source-map-v3 file at `<output>.wasm.map`. Its single generated line uses absolute Wasm offsets as generated columns and Base64-VLQ segments for source, zero-based line/column, and function-name deltas. Source text is embedded through `sourcesContent`, so developer tools do not depend on the output directory mirroring the project tree. A URI-percent-encoded `sourceMappingURL` custom section containing the sidecar filename is appended to the final module, allowing compatible browser developer tools to discover it. Tests validate marker counts, offsets, VLQ encoding, both custom sections, and import-shifted function indexes.

WebGL2 pipelines expose `std::web::webgl_supported(selector) -> Bool` and use `std::web::webgl_create(selector, vertex_shader, fragment_shader, vertices_json, indices_json) -> Int`, `webgl_uniform_f32(scene, name, numerator, denominator) -> Bool`, `webgl_draw(scene, clear_color_json) -> Bool`, and `webgl_delete(scene) -> Bool`. Creation compiles and links GLSL ES 3 shaders with full driver logs, requires a vec2 `a_position` attribute, caps each shader at 1 MiB, validates finite Float32 vertex/index JSON with hard limits, uploads Float32/Uint16 buffers into a VAO, and retains explicit GPU resources by scene ID. Drawing checks context loss, sets viewport/clear color, issues indexed triangles, and reports GL errors. Uniform ratios preserve fractional values despite the current integer Wasm ABI. Deletion releases buffers, VAO and program. The browser example draws a real GPU triangle.

Numeric/scalar arrays and tuples live in managed linear memory. `NewArray`/`NewTuple` reserve a checked descriptor plus contiguous 8-byte ABI slots through the shared growable allocator; handles remain `i64`, `len` reads the logical element count, and `Index` performs signed-negative and unsigned upper-bound checks before `i64.load`. Elements may also be string or nested collection handles because slots preserve the full scalar ABI.

Persistent operations include `std::array::set`, `push`, `pop`, half-open `slice`, and `concat(left, right)`. Concat validates combined memory32 capacity, allocates one exact payload, then performs two ordered `memory.copy` operations; empty inputs are valid and both originals remain unchanged. Slice validates `0 <= start <= end <= len`. VM and Wasm semantics match for all operations and preserve nested/string handles. Individual reclamation is not implemented yet.

The managed heap exposes telemetry/limits plus manual checkpoints and nested LIFO scopes. `heap_scope_begin() -> Int` allocates an internal record containing its checkpoint and parent; `heap_scope_end(token) -> Bool` succeeds only for the current top scope, bulk-zeroes/reclaims that scope, restores its parent, and updates telemetry. Ending an outer token before its inner scope safely returns false without changing memory. A raw successful `heap_restore` clears the scope stack because its records may have been reclaimed. Handles created inside an ended scope become invalid and must not escape. Peak/reset counters remain observable. This is deterministic stack-region reclamation, not tracing GC.

Portable bytecode preserves legacy collection/enum tags and adds recursive `ArrayOf(T)`, `TupleOf(...)`, and `EnumOf(name, generics)` metadata. Type conversion records generic arguments such as `Option<Point>` and `Result<[int], Error>`; Wasm propagates them through parameters/direct returns. Enum construction captures the concrete payload kind, while `EnumPayload` recovers it, enabling chains such as `make_option()[payload].field` without guessed layouts. Variant-specific payload maps now distinguish built-ins: `Option::Some` selects generic 0, while `Result::Ok`/`Result::Err` select generics 0/1. Enum construction records its concrete variant payload; match lowering's preceding `EnumIs` refines `EnumPayload`, so `Result<int, Error>::Err` can safely expose `Error` fields across calls. Unknown/custom multi-generic mappings remain conservative rather than guessed. All additions remain serde/backward-compatible. Map prerequisites now include allocation-free UTF-8 primitives: `std::text::equals(left, right)` performs bounded byte comparison, and `std::text::hash64(text)` computes stable FNV-1a over the same UTF-8 bytes using wrapping i64 arithmetic. Equal dynamic/static strings therefore produce identical hashes, while collisions can be resolved by the content comparator. The next map layout stores hash + key handle + value. Maps and tracing reclamation remain pending.
