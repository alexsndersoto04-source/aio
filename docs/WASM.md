# TITAN WebAssembly Backend

`titan wasm <project>` emits a real WebAssembly module with exported `main` and named functions. The backend lowers integer/bool/nil constants, locals, arithmetic, signed division/remainder, logical and bitwise operations, comparisons, direct calls and returns to Wasm instructions.

Titan's bytecode control-flow graph is validated with a work-list stack analysis. Operand-stack values are assigned to Wasm locals, and forward/backward branches are lowered through a structured Wasm dispatch loop. This supports `if`/`else`, lazy boolean expressions, `while`, `loop`, `break`, and `continue` without embedding or calling the Titan VM. Invalid branch targets, stack underflow, inconsistent merge heights, bad locals/calls, and declared stack-limit violations produce compilation errors. Generated bytes, including forward branches and backward loops, are validated in tests with `wasmparser`.

UTF-8 string literals are stored in an exported Wasm 32-bit linear memory. A string value uses an `i64` ABI handle: the low 32 bits are the byte pointer and the high 32 bits are the byte length, so JavaScript can decode it without copying through the Titan VM. Four bytes immediately before the payload store the Unicode scalar count; Titan `len(string)` loads that count and therefore preserves Titan/VM Unicode semantics rather than returning UTF-8 bytes. Memory sizing is calculated from the complete string table, overflows are rejected, and invalid string-table references fail compilation.

Dynamic string allocation and concatenation are not implemented yet. A function containing string literals and `Add` is conservatively rejected to prevent accidental numeric addition of handles. Collections remain explicitly unsupported. Dynamic strings/allocator support, browser imports, DOM bindings and source maps are subsequent Phase 6 blocks.
